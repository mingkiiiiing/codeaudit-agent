## 2. 设计决策记录

1. **风险聚焦默认值不翻**（0=全量）：遵循 W7「负收益诚实回退」惯例——开关先落地，flash 对数（§5）验证 P50 与 Precision 判据后再翻默认。判据：P50 ≤ 300 s/KLOC 且 Precision 降幅 ≤ 3pp。
2. **imported_by 度数不进 MVP**：`dependencies(direction="imported_by")` 逐文件反查是全表扫描，2000 文件 O(n²) 不可接受；风险分用规则命中加权已足够区分（规则通道本来就是全量兜底）。
3. **severity_overrides 改写点在 hits 层而非 Issue 层**：`_hints_of`（LLM 引导）与 `apply_verify`（复核触发）都消费 hits/severity，若在 hits_to_issues 之后改 Issue 会漏两处；hits 层单点改写三处同口径。
4. **折叠只动 tool 消息 content**：OpenAI 协议要求 assistant.tool_calls 与 tool 消息逐 id 配对，删除消息破坏结构；assistant 的 tool_calls 字段同样不可触碰。
5. **W22-D 挂点在 cli 而非 lifespan**：lifespan/create_app 拿不到 host 参数；cli 侧紧邻 `--workers<1` 校验的现成范式（中文报错+退出码+monkeypatch 测试形态）。
6. **W22-F 多文件聚焦不做**：沙箱 `run_tests` 为单 target argv 口径，多文件需沙箱层支持多 target（后续项）；单文件聚焦已捕获大部分收益（全库→单文件）。

## 3. 已知边界（诚实声明）

- `ignore_paths` 不影响索引构建与后处理扫描器（克隆/死代码/depcheck 仍全库）——语义是"检测口径裁剪"而非"接入裁剪"。
- W22-F 聚焦依赖索引质量：动态调用（getattr/反射）的 callers 解析不到时回退整库（诚实降级）。
- W22-A 折叠后 LLM 失去被折叠的完整工具结果细节（信息换预算，标记中保留原长度供模型感知截断事实）。
- W22-D 只拦截 CLI 入口；直接 `uvicorn server.app:app` 绕过 CLI 的部署不受保护（README 部署文档应指引 CLI 启动）。
