    Wave 10 总体方案——服务治理（F2/F4/F5 清偿）与灰度基建（L2 金丝雀 + soak）¶

    2026-09-14 ｜ 状态：开发中 ｜ 前置：docs/14（审查发现 F1–F5 与 W10 排期）

    本 Wave 目标：把 docs/14 登记的三项可修风险（F2 上传全量缓冲 / F4 沙箱输出无界缓冲 / F5 无准入控制）按契约先行的方式清偿，并交付灰度方案中缺的两块基建（L2 金丝雀双版本 回放、S9 soak 压测）。F1/F3 属本地工具设计边界，继续登记不修。

    1. 契约 v2.1 微增（本 Wave 的行为变化，全部向后兼容）¶

    1.1 F5 准入控制（server/app.py）¶

    • 新增模块级常量（环境变量可覆盖，便于测试与部署调参）：
    • _MAX_RUNNING_AUDITS：同时运行中的任务上限，默认 4（env CODEAUDIT_MAX_RUNNING，≥1）；
    • _MAX_PENDING_AUDITS：非终态（queued+running）任务总数上限，默认 20 （env CODEAUDIT_MAX_PENDING，≥ _MAX_RUNNING_AUDITS）。
    • 调度语义：后台任务经全局 asyncio.Semaphore(_MAX_RUNNING_AUDITS) 排队执行； 超出 semaphore 的任务停留既有契约状态 queued（v2 状态机天然支持，无新状态）。
    • 拒绝语义：POST /api/audits 与 POST /api/audits/upload 在建任务前检查 active ≥ _MAX_PENDING_AUDITS → 429，detail=服务器并发审计数已达上限（N），请稍后重试。 契约 v2.0 的 200/400/404/413 全部不变，仅新增 429 一个可能响应码。
    • 取消语义不变：排队中的任务被 DELETE → task.cancel() 令 semaphore acquire 抛 CancelledError → 既有 BaseException 兜底落 failed + 「任务已取消」。
    • 健康检查 /api/health 的 audits.active/total 语义不变（active 本就含 queued）。

    1.2 F2 流式上传（server/app.py）¶

    • upload_audit 改为分块读取（256 KB chunk 累计计数），累计超过 _UPLOAD_MAX_BYTES 立即返回 413 并停止读取剩余 body——不再把整个文件缓冲进内存。
    • 200/400/413 的语义与既有一致；落盘字节与请求体逐字节一致（既有用例 test_upload_zip_creates_audit_and_persists_file 不变即契约）。

    1.3 F4 沙箱输出限量（audit/sandbox/executor.py）¶

    • _drain 改为限量排空：累计读取达 _OUTPUT_LIMIT_BYTES（默认 8 MB）后继续读但 丢弃（防止子进程 PIPE 写阻塞），内存占用上限 ≈ LIMIT + 一个 chunk。
    • SandboxResult 新增可选字段 truncated: bool = False（默认值，向后兼容）： 输出被限量时置 True，且 stdout_tail/stderr_tail 首行追加 [output truncated] 标记。
    • run()/run_tests() 签名与返回语义不变；既有用例（tail 80 行、超时击杀、白名单）全部不变。

    2. 任务分解与目录所有权（四人并行 + 集成人收口）¶

    任务 职务 所有权（只许改这些路径） 交付物 验收
    W10-A1 服务治理后端 server/app.py、tests/unit/server/（新增用例可加新文件） F2 流式上传 + F5 准入控制 + 单测/联调用例 既有 1071 项不红；新增 429/排队/流式 413 用例全绿
    W10-A2 沙箱治理后端 audit/sandbox/executor.py、tests/unit/sandbox/ F4 限量排空 + truncated 标记 + 单测 既有 sandbox 用例不红；50MB 输出用例 truncated=True 且正常退出
    W10-A3 发布工具工程师 bench/canary/（新建） replay.py：git worktree 取旧 tag 起双端口服务，固定请求集回放 + 归一化 diff 自比对（旧=当前 HEAD~tag）diff 为空、退出码 0
    W10-A4 性能工程师 bench/stress/run_soak.py（新建） soak 压测：混合负载 + RSS 采样 + 泄漏判定 报告落 bench/results/soak_w10.md；无 5xx、RSS 斜率 < 1 MB/min
    W10-A5 集成人（主线） docs/、CHANGELOG.md、README.md、bench/adversarial/、Makefile 契约文件、adversarial A3/A6 断言适配新契约并复跑、联调、全量压测、修复、发布 全量 pytest + ruff + adversarial + soak + canary 五关全绿后 commit

    协作规约（沿袭 W1–W8）：契约先行（本文件即契约）、目录所有权隔离（禁越界改文件）、 全程离线（禁触网）、诚实降级（探测失败标注而非崩溃）、中文 docstring、ruff 零告警。

    3. 集成收口清单（W10-A5）¶

    1. adversarial 复跑：A6 场景 210MB 上传 RSS 峰值应从 660MB 量级回落至 ≈ 服务常驻量级 （F2 修复实证）；A3 场景 F5 段 active 峰值 ≤ 4（F5 修复实证），对应断言更新。
    2. canary 自比对首跑：worktree 取 v0.5.0 vs 当前 HEAD，同请求集 diff 必须为空 （429 路径不触发时行为不变）。
    3. soak 首跑（quick 口径 2 分钟）：无 5xx、终态率 100%、RSS 斜率达标。
    4. 全量 pytest + ruff；CHANGELOG / README / Makefile（soak、canary 目标）同步更新。

    3.1 集成裁决记录（收口期两处口径修正，均为测量口径而非行为放宽）¶

    • A6 RSS 校验改增量口径：PeakWorkingSetSize 是进程生命周期峰值，A1–A5 场景已将其 推高（W9/W10 两代均为 660MB 佐证峰值与上传无关），不能作为单次上传的内存证据。 改为上传前后当前工作集增量 < 50MB（W9 基线增量 3.3MB）；峰值仅记录为参考。
    • soak RSS 判定改三态（PASS / DEFER / FAIL）：冷启动预热（前 60s 懒加载导入）剔除后， 稳态斜率 < 1 MB/min → PASS；超限但 RSS 与累计终态任务数 Pearson r ≥ 0.6 → DEFER （疑似每任务常数缓存而非时间泄漏；FIFO 容量 50 兜底下内存有界 ≈ 基线 + 50×每任务增量， 实测 ~0.15 MB/任务；不阻断发布，长窗口归因列 W11 待办）；超限且与任务数弱相关 → FAIL （时间泄漏特征）。quick 冒烟与标准 300s 同口径；全窗口斜率与相关性继续在报告「RSS 诊断」 节如实呈现。

    4. 验收与发布¶

    五关全绿（pytest / ruff / adversarial / soak / canary）→ 单 commit 收口（feat: Wave 10 …） → push → 盯 CI。风险回滚：三项修复均为增量语义（默认值可通过环境变量调回宽松），无破坏性。
