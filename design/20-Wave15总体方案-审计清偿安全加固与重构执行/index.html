    docs/20 — Wave 15 总体方案：审计清偿、安全加固与重构执行¶

    状态：执行中（2026-09-15 立项）。来源：2026-09-15 全库四维审计（代码质量 82 / 安全合规 66 / 架构 78 / 重构落地 68，总分 76，技术债约 30 人日）。 本波范围 = 审计 P0 全部 + P1 核心；P2 与契约变更项明确排除（见 §3 非目标）。 开发模式：六卡并行（目录所有权强隔离，卡间零文件交集）→ 单卡验收（审查+ scoped 测试+压力项）→ 集成人统一联调（全量回归 + 前端三门禁 + 压测 + 修复）。

    1. 背景与审计结论摘要（本波依据）¶

    3. 非目标（本波明确不做）¶

    • isort/pyupgrade 启用（存量批量改造，独立专项）。
    • web/ 旧前端下线、agent/agents 双包合并、confkit 更名（纯命名治理，P2）。
    • audit/indexer/store.py 并发加固（当前单线程使用安全，P2 文档化即可）。
    • pip 完整锁文件（Dependabot + pip-audit 门禁已覆盖，锁文件另行评估）。

    4. 接口契约（并行卡共同遵守，集成人不改语义）¶

    4.1 卡A 新增配置（audit/config.py AuditConfig 字段 + 分层来源）¶

    • api_token: str = ""——来源 env CODEAUDIT_API_TOKEN；空 = 鉴权关闭（本机开发态默认，兼容既有行为）；非空时 /api/*（除 GET /api/health）要求 Authorization: Bearer <token> 或 X-API-Token: <token>，失败 401。启动时 token 为空打 WARNING 日志（无鉴权提醒）。
    • allowed_source_roots: list[str] = []——来源 env CODEAUDIT_SOURCE_ROOTS（os.pathsep 分隔）；非空时 POST /api/audits 的 source_path 必须位于任一根之内（resolve 后 relative_to 判定），越界 400；空 = 不限制（兼容）。
    • rate_limit_per_min: int = 0——来源 env CODEAUDIT_RATE_LIMIT；>0 时对写方法（POST/DELETE）按客户端 IP 滑动窗口限流，超限 429；0 = 关闭（既有测试不受扰）。
    • SSE 并发上限：模块常量 _MAX_SSE_STREAMS = 50，超限新建 SSE 返回 429（不做排队）。

    4.2 卡A 脱敏（LLM 路径）¶

    • audit/detect/base.py 新增模块级 mask_secret_text(text: str) -> str：对单行文本做密钥形态打码（复用/对齐 W14 mask 语义，占位 ********）；mask_snippet 既有语义不变。
    • review.py _issue_from_payload：snippet = mask_snippet(...)（或等效套用），evidence 逐条过 mask_secret_text。
    • 验收：新增 LLM 路径脱敏测试（FakeLLM 返回含密钥行区间的 payload → 断言报告 Issue 中无明文密钥）；既有 test_secret_masking.py 全绿。

    4.3 卡B 存储契约（audit/taskstore.py）¶

    • 连接即设 PRAGMA busy_timeout=5000；写操作遇 sqlite3.OperationalError: database is locked 指数退避重试（≤3 次）。
    • append_event 改单事务 BEGIN IMMEDIATE + INSERT ... SELECT COALESCE(MAX(seq),0)+1（跨连接并发追加 seq 严格单调、无 PK 冲突）。
    • sweep_interrupted(grace_seconds: int = 0) 新增参数：>0 时仅清扫 updated_at 早于 now-grace 的 queued/running 行（多 worker 部署设 CODEAUDIT_SWEEP_GRACE_SEC 规避兄弟 worker 复活竞态）；0 = 既有语义不变。行表需有 updated_at 维护（若无则补充，写入路径统一 touch）。
    • server 侧接线归卡A（其所有权）：lifespan 改 _get_store().sweep_interrupted(grace_seconds=_int_from_env("CODEAUDIT_SWEEP_GRACE_SEC", 0, minimum=0))，并在 lifespan yield 后 close store（TaskStore.close 已幂等）。
    • 验收：新增双连接并发压测（2 实例 × N 线程 × M 事件，断言零 OperationalError、seq 严格递增、事件零丢失）；grace 语义单测。

    4.4 卡C CI/依赖¶

    • pyproject：python-multipart>=0.0.18、jinja2>=3.1.6、fastapi>=0.115（带起 starlette>=0.40）；先实测当前环境可满足再改下限。
    • ci.yml：删 issues: write；3.13 覆盖率 job 加 --cov-fail-under=<基线>（先跑 --cov 实测取整十向下基线，注释注明棘轮策略）；新增 pip-audit step（continue-on-error: false）。
    • 新增 .github/workflows/pr-audit.yml：PR 触发，离线模式自审计（python cli.py run <repo> --diff origin/main --fail-on critical --format sarif > codeaudit.sarif），上传 SARIF artifact；无 secrets 依赖。
    • tests/unit/ci/test_ci_config.py 同步断言更新。

    4.5 卡D 规则族收敛¶

    • 新建 audit/detect/rules/_scan_common.py（或同名承载）：收纳 _python_common/_js_common 逐字重复的通用件（call_span/find_call/enclosing_function/indent_width/is_blank 等），两个 common 改为转发导入，公共函数签名与行为不变。
    • 同构规则（TodoFixme/LongFunction/DeepNesting/MagicNumber 至少这四类）参数化基类或工厂（make_xxx_rule(lang_prefix, ...)），python.py/javascript.py 改为薄封装；规则 id、severity、文案语义、命中结果完全不变。
    • errors.py 删除 IndexBuildError/ReportError（先 grep 确认零引用）。
    • 验收：新增 test_rule_family_parity_w15.py（PY/JS 同名规则对同构夹具命中等价性）；tests/unit/detect 全绿（夹具金标准命中数不得变化）。

    4.6 卡E 重构执行闭环¶

    • fix/verifier.py：Python 文件语法校验叠加 ast.parse（tree-sitter + ast 双保险，ast 失败即 syntax 失败回滚）；其他语言维持 tree-sitter 单校验（不支持语言仍返回 True 不阻塞，语义不变）。
    • fix/patcher.py + sandbox/executor.py：散落超时 30 / 截断 500 / 截断 300 / Docker "512m" 提为具名模块常量（值不变）。
    • 重构 proposal→patch 最小闭环（契约零改动方案）：refactor/stage 对 top-N（≤3，confidence 过滤）启发式 proposal 合成 Issue(source=LLM, severity=medium, title="[Refactor] <proposal.title>", ...) 喂给既有 fix 阶段管线（LLM 生成 diff → 校验 → 应用 → tree-sitter+ast 校验 → 沙箱测试 → 四态 FixStatus/回滚），产物自然进入 report.patches；开关沿用 enable_llm_review && llm_available，离线零行为变化。models.py 不加新字段。
    • 验收：新增 test_refactor_patch_w15.py（FakeLLM 脚本化：合法 patch→verified；坏语法 patch→回滚 needs-review）；tests/unit/fix + tests/unit/refactor 全绿。

    4.7 卡F 测试盲区¶

    • 新建 tests/unit/utils/test_utils.py（extract_json/fingerprint/truncate/make_id 边界全覆盖）、tests/unit/pipeline/test_context.py（PipelineContext/EventEmitter 契约）、tests/unit/agents/test_prompts.py（PROMPT_VERSION/模板装载）、tests/unit/architecture/test_architecture_logging.py（静默吞噬路径存在记账/日志断言——只加测试不改 architecture.py，若现状确无记账则测试标注 expected-fail 上报集成人裁决）。
    • frontend 新增 SevTag.test.tsx、StatusTag.test.tsx（渲染分级断言）；cd frontend && npx vitest run 全绿。
    • 不改任何生产代码；发现的生产缺陷只记录上报。

    5. 验收与集成流程¶

    1. 单卡验收（每卡完成后立即）：集成人审查 diff（对照所有权与契约）→ 跑该卡 scoped 测试 → 卡内压力项（卡B 并发压测 / 卡A 限流与 SSE 上限测试）→ 问题当卡修复或退回。
    2. 统一联调（六卡齐后）：ruff 全仓 → pytest 全量（基线 1242 passed，零 fail 零 error）→ 前端 tsc+vitest+build → CHANGELOG [Unreleased] 追加 W15 段（集成人）→ 服务级压测（若 bench/soak 脚本可在 5 分钟内完成则跑，否则以卡A/B 压测项 + 全量回归替代并如实说明）。
    3. 报备清单（集成阶段向用户提出，批准后另起 W15.5）：models.py schema_version 校验、CallEdge 死模型清理、Rate-limit/SSE 上限是否改默认开启。

    6. 风险与回滚¶

    • 所有新增治理均 opt-in（env 缺省 = 既有行为），单点回滚 = 还原对应卡文件；规则收敛（卡D）以「夹具命中金标准不变」为硬门禁，任何命中差异即回退该重构。
    • 并行开发基于同一工作区（W14 未提交改动之上），目录所有权隔离冲突为零；集成人统一负责文档/CHANGELOG 收口。
