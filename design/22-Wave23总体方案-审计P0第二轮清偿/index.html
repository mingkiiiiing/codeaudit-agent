    卡 文件 交付物

    2. 设计决策记录¶

    1. apply 默认 dry-run：对源码写入是本项目第一个"出 audit 报告之外副作用"的入口，安全默认与 W22-D（非回环强制 token）同哲学——危险动作显式 --yes。
    2. sha256 指纹防覆盖 + all-or-nothing：审计与应用之间用户可能手改源码；逐 patch 校验、任一拒绝整体不落盘，避免半应用状态（半应用比不应用更危险）。
    3. AST 只做置信佐证、不做命中删改：行为等价铁律（金标 P=1.000/R=0.844 逐位一致为验收门）——AST 佐证失败或 tree=None 时行级命中原样保留，行级逻辑仍是兜底路径；只有新规则 PY-NONE-DEREF 是 AST-only（其命中集合增量、不触碰存量）。
    4. rule_id 走 evidence 约定而非改契约：Patch/Issue 模型无 rule_id 字段，models.py 是契约文件；detect 引擎写入的 rule:XXX 证据行已被 SARIF 导出消费，复用同款解析零契约变化。
    5. commit message 纯拼接零 token：模板化输出确定性可测（15 用例），不引入 LLM 非确定性；needs-review/failed 状态如实进 PR 描述（不粉饰）。
    6. 测试盲区只做 TOP 20 + methodology 诚实标注：resolved_ratio（当前约 0.178 口径）偏低时反查两种误差都放大，能力边界写进渲染而非藏在实现里。

    3. 已知边界（诚实声明）¶

    • apply 只处理 Patch（fix 阶段产物）；RefactorProposal 类方案性建议仍走报告阅读路径。
    • 老报告（无 target_sha256）不能落盘只能预览——重新审计后即可获得指纹。
    • PY-NONE-DEREF 覆盖"同函数内直接 None 赋值流"，跨函数/属性路径传播不在本轮口径（AST-only 保守起步）。
    • untested_hotspots 对动态调用（getattr/反射）悲观、对 resolved_ratio 敏感，节内已附 methodology 说明。
    • commit message 的 category 取 Issue 既有分类，不做语义归并；unknown-rule 条目会出现在涉及规则清单（与摘要计数口径一致）。
