    Wave 22 总体方案——审计报告短期 P0 清偿¶

    2026-09-16 ｜ 状态：已完成（对数结论见 §5） ｜ 前置：2026-09-16 系统性审查报告（综合 59/100，四大维度 22 子项）

    用户指令：依据审计报告制定并执行短期 P0；在线验证使用 GLM-5.3 Flash。

    0. 背景与选卡依据¶

    系统性审查给出的短期路线图四项 + 一项低成本高收益附加项，共六卡：

    卡 审计条目 一句话
    W22-D 2.2-1 serve --host 0.0.0.0 无 token 裸奔——部署安全洞
    W22-C 2.3-1 / P0-4 规则不可按项目裁剪（禁用/降级/路径白名单）——企业落地第一道墙
    W22-A 3.3-2 工具循环消息不裁剪，completion:prompt=3:1 异常——在线成本根因之一
    W22-B 3.1-1 / 3.3-1 / P0-1 LLM 全量逐文件审查——在线 1398 s/KLOC 的第一阻塞项
    W22-F 1.4-1 Patch 验证跑全量测试——大项目验证耗时放大器
    W22-E P0-5 PROMPT v3 无基准复跑，0.884 数字对当前代码失效

    1. 任务卡与所有权¶

    卡 文件 交付物

    W22-C audit/config.py、audit/detect/engine.py、cli.py、tests 三配置字段（默认空=零行为变化）：disabled_rules（并入既有 extra["disabled_rules"] 拦截点，run_rules/run_detection 双入口接线）、severity_overrides（hits 聚合后 hits_to_issues 前统一改写，hints/verify/报告三处同口径）、ignore_paths（build_rule_contexts 内 fnmatch+目录前缀过滤，一处覆盖规则扫描与 LLM 审查清单）；未知规则 id/非法严重度记 extra["rule_config_warnings"]；CLI --disable-rule/--ignore-path（append）
    W22-A audit/agent/base.py、audit/agent/runtime.py、audit/config.py、audit/agents/review.py、tests AgentLimits.message_budget_chars（默认 0=不限）+ AuditConfig.agent_message_budget（默认 60_000）；runtime 每轮 chat 前超预算从最旧 tool 消息折叠 content（保留 160 字符前缀+标记；只缩短不删消息保 tool_call/tool 配对；标记前缀幂等；折叠尽仍超则停——不动 user/system）。契约文件例外报备：agent/base.py 标注"勿改"，本次为带默认值增量字段（所有既有构造点零变化），消费点同批次真实接线

    W22-F audit/fix/verifier.py、audit/fix/stage.py、tests run_existing_tests(target="") 透传（沙箱层原生支持，零改动）；_affected_test_target：issue 行区间覆盖符号经 call_chain(direction="callers",depth=1) 收集直接调用方中的 test_*.py/_*_test.py，多文件取字典序首文件，按文件缓存；聚焦运行 exit 5（未收集到用例）→ 整库兜底复跑；fix_stats 新增 focused_tests_runs 计数
    W22-E bench/ablation.py、bench/w22_focus_compare.py、docs/21、CHANGELOG 消融第 8 组 llm_focus（top 25）；一次性对数脚本（full + llm_focus，10 项目 240 金标）；flash 真跑结论（§5）

    2. 设计决策记录¶

    1. 风险聚焦默认值不翻（0=全量）：遵循 W7「负收益诚实回退」惯例——开关先落地，flash 对数（§5）验证 P50 与 Precision 判据后再翻默认。判据：P50 ≤ 300 s/KLOC 且 Precision 降幅 ≤ 3pp。
    2. imported_by 度数不进 MVP：dependencies(direction="imported_by") 逐文件反查是全表扫描，2000 文件 O(n²) 不可接受；风险分用规则命中加权已足够区分（规则通道本来就是全量兜底）。
    3. severity_overrides 改写点在 hits 层而非 Issue 层：_hints_of（LLM 引导）与 apply_verify（复核触发）都消费 hits/severity，若在 hits_to_issues 之后改 Issue 会漏两处；hits 层单点改写三处同口径。
    4. 折叠只动 tool 消息 content：OpenAI 协议要求 assistant.tool_calls 与 tool 消息逐 id 配对，删除消息破坏结构；assistant 的 tool_calls 字段同样不可触碰。
    5. W22-D 挂点在 cli 而非 lifespan：lifespan/create_app 拿不到 host 参数；cli 侧紧邻 --workers<1 校验的现成范式（中文报错+退出码+monkeypatch 测试形态）。
    6. W22-F 多文件聚焦不做：沙箱 run_tests 为单 target argv 口径，多文件需沙箱层支持多 target（后续项）；单文件聚焦已捕获大部分收益（全库→单文件）。

    3. 已知边界（诚实声明）¶

    • ignore_paths 不影响索引构建与后处理扫描器（克隆/死代码/depcheck 仍全库）——语义是"检测口径裁剪"而非"接入裁剪"。
    • W22-F 聚焦依赖索引质量：动态调用（getattr/反射）的 callers 解析不到时回退整库（诚实降级）。
    • W22-A 折叠后 LLM 失去被折叠的完整工具结果细节（信息换预算，标记中保留原长度供模型感知截断事实）。
    • W22-D 只拦截 CLI 入口；直接 uvicorn server.app:app 绕过 CLI 的部署不受保护（README 部署文档应指引 CLI 启动）。

    4. 验收¶

    • 全量 pytest 绿（基线 1879 + 新增 34：serve 10 / config 4 / engine 规则配置 12 / 选择器 8 / 消息预算 6 / fix 聚焦 8——以实际收集数为准）。

    5. flash 对数结论（W22-B 翻默认判据）¶

    • 命令：python -m bench.w22_focus_compare（10 项目 / 240 金标 / critical+high 层 / glm-5.3-flash；.env 自动加载口径与 CLI 一致）。
    • 判据：P50 ≤ 300 s/KLOC 且 Precision 降幅 ≤ 3pp（对 full 组基线）。
    • 执行状态（2026-09-16）：未执行成功——GLM 账户余额不足。启动后全部 LLM 调用返回 HTTP 429（"余额不足或无可用资源包，请充值"），流水线诚实降级运行（架构理解降级启发式），该场景下的对数数据无效，任务已中止且无效产物未落盘。dry-run 预检（零 Key）通过。
    • 待办：账户充值后重跑 python -m bench.w22_focus_compare，结果回填本节并写入 bench/results/run_<日期>_w22_focus.md；判据达标才翻 W22-B 默认值（不达标记录原因并维持默认关闭）。
    • 定性修正（2026-09-17，用户澄清）：本账户为 GLM Coding Plan（套餐制），此前的 HTTP 429（"余额不足或无可用资源包"）实为套餐限流/配额窗口而非余额耗尽——P0-1/P0-7 的"充值后复跑"表述不成立，正确口径为：套餐配额可用时直接重试对数（如遇 429 退避重试或换时段），无外部充值依赖。
